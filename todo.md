# CKB-VM cycle priorities for the 500-signature aggregate

The experimental prover produced a 292,456-byte proof. The release verifier accepted it in **605,129,810 CKB-VM cycles**. The flamegraph accounts for **604,623,449 instruction cycles**. The embedded bytecode evaluator is the largest call path at **354,002,101 cycles (58.55%)**. Its largest named child is software carry-less multiplication at **105,076,613 cycles**. [Flamegraph](bench/profiles/sphincs-500.svg) · [Folded stacks](bench/profiles/sphincs-500.folded.gz)

## Priorities, highest first

Percentages use the flamegraph total. Self cycles include inlined work. Inclusive cycles also include callees. The ranking weighs the work each change could still remove after earlier changes. Several rows cover the same instructions, so their costs cannot be added as projected savings.

1. **Completed. Use RV64 carry-less multiply instructions for binary-field products.** In the baseline, `verifier::field::clmul` consumed **184,250,850 self cycles (30.47%)**, or 379 cycles per call across 486,150 calls. The RV64 Zbc build now uses `clmul` and `clmulh`. Both halves matched the portable product across 3,025 operand pairs in CKB-VM. Fast-mode replay of the same 500-signature proof fell from **605,129,810 to 383,247,760 cycles**, saving **221,882,050 cycles (36.67%)**. [Field multiplication](crates/verifier/src/field.rs) · [CKB target flags](bench/ckb/build)

2. **Reduce the cost of inflating the fixed guest bytecode.** Named `miniz_oxide::inflate` frames account for **84,129,395 cycles (13.91%)**. Of these, 65.24M are in the transfer routine itself and 18.23M in Huffman tree initialization itself. The verifier inflates 277 nonempty blocks covering 254 distinct compressed ranges. Trial a block decoder with cheap literal and match copies. As a size check, an offline LZ4-HC encoding of the unique blocks used 1,830,486 bytes versus 1,486,012 for DEFLATE. Separating the words, counts and deltas into byte planes before LZ4-HC brought it to 1,646,353 bytes. Measure the complete verifier's cycles and memory fit before picking an encoding. [Block generator](bench/ckb/build.rs) · [CKB evaluator](bench/ckb/src/main.rs)

3. **Authenticate each pruned Merkle phase once.** Proof decoding consumed **51.13M inclusive cycles**, including **33.59M** in Keccak permutations and their callees while rebuilding the tree. Later, `Transcript::merkle` consumed **49.70M**, including **45.98M** in the same permutation while walking the expanded paths. Keep the compact phase and compute its root once. Bind that root to the transcript commitment and check the sampled query order, dimensions, canonical encoding and leaf values before using the rows. This also avoids cloning a sibling vector per query. [Wire decoding](crates/verifier/src/wire.rs) · [Transcript checks](crates/verifier/src/transcript.rs) · [Path hashing](crates/verifier/src/merkle.rs)

4. **Reduce position-by-position work in the embedded evaluator.** The evaluator has **162,034,784 self cycles (26.80%)** shared by inlined inflation, record parsing and evaluation. The profile cannot split that figure further. The actual table contains **2,194,969 position deltas**, including 744,743 equal to one, and 77,023 of 138,208 word groups have a single position. Give singletons a direct lookup. For long consecutive runs, test an encoded range and two prefix-XOR lookups into the low-coordinate weights. Measure the cost of constructing the prefix table and its peak scratch space against the saved lookups. [Block layout](bench/ckb/build.rs) · [Position loop](bench/ckb/src/main.rs)

5. **Lower the cost of the remaining Keccak-f permutations.** `verifier::hash::keccak_f` consumed **81,287,010 self cycles (13.44%)**, or **85.32M** with callees. Most calls are in the two Merkle paths in priority 3. The same binary already has a second scalar permutation, `keccak256::keccak_f`, for hashing the public claims. Compare the two on identical states and inspect the working-state copies in the verifier implementation. Measure per-permutation cost and the residual whole-proof gain after Merkle deduplication. [Verifier permutation](crates/verifier/src/hash.rs) · [Shared Keccak implementation](crates/keccak256/src/lib.rs)

6. **Exploit the zero prefix in first-level WHIR row folds.** `fold_row` consumed **16,987,799 inclusive cycles (2.81%)** over 346 rows. The captured first phase has 218 rows, each with 27 leading zero words out of 64. The current path expands the zeros, reverses the row, converts every word to an extension element and folds every pair. Carry the validated zero extent into the fold, skip all-zero pairs and use base-field operands in the first round. Check the mixed pair at the zero boundary against the generic fold. [WHIR folding](crates/verifier/src/whir.rs) · [Row decoding](crates/verifier/src/wire.rs)

7. **Batch field reductions in the Keccak proof's lane dot products.** Twelve `verify_layer` calls consumed **58.62M inclusive cycles**. The 25 lane dot products per layer and construction of the next 1,600 weights each spent **21.83M** in `clmul` alone. Re-profile after priority 1. For the dot products, XOR-accumulate unreduced products before reducing once per lane. Compare against the existing 64-element dot product. The separate outer-product cost remains visible in the flamegraph and provides a check on the scope of the gain. [Keccak layer](crates/verifier/src/keccak.rs) · [Dot product](crates/verifier/src/multilinear.rs)

8. **Reuse WHIR subspace evaluations between query and terminal checks.** `Subspace::at` consumed **11.54M inclusive cycles (1.91%)**. Its field multiplier alone took **4.98M** on the first pass and **4.90M** under the terminal weight closure. Nonfinal levels evaluate the same normalized subspace polynomials at the same queries twice. Trial retaining the values needed by `induced_weight`, or recomputing them from a small table for the fixed binary domain. Compare cycles and live heap across all four nonfinal phases. [Subspace and terminal weight](crates/verifier/src/whir.rs)

9. **Retune the equality-weight lookup tables for RV64.** Under bytecode evaluation, `Scaled::mul` took **5,931,008 self cycles (0.98%)** over 16,384 calls. The current six-bit window uses 22 table lookups per extension product, and the switch to tables starts at 256 uses. After priority 1, compare direct multiplication against the table on the actual equality-kernel sizes, including table setup. The 14-coordinate low table is the first case to measure. [Equality kernel](crates/verifier/src/multilinear.rs) · [Scaling tables](crates/verifier/src/field.rs) · [Bytecode split](crates/verifier/src/bytecode.rs)

10. **Compute only the consumed columns in Keccak openings.** The two `keccak::open` calls together consumed **4,906,367 inclusive cycles (0.81%)**. The committed-output check reads only `weights[0]` after computing all 64 columns. Give that check a one-column accumulation. The input check consumes all 64 columns, but its segment scales can be summed per lane before multiplying that lane's 64 weights. Compare the scalar output, full input row and transcript consumption with the existing evaluator. [Opening and both callers](crates/verifier/src/keccak.rs)

## Measurement and replay

Measured at revision `8c6b854ce` with Rust 1.100.0 and `ckb-debugger` 1.1.1. The benchmark also reported 2,753,300 leanVM guest steps. The optimization target above is the CKB-VM cost of verifying the resulting proof.

```sh
RUSTUP_TOOLCHAIN=stable cargo leanvm-bench --prover experimental aggregate --sphincs 500 --log-inv-rate 1 --repeat 1
```

The transaction, claims and witness were copied from the benchmark's temporary directory. For symbol resolution, the same release build was linked with its symbol table retained. Its allocated code and data sections matched the stripped verifier in address, size and contents, and the BSS layout matched. Both binaries returned 0 at 605,129,810 cycles in fast mode. The debugger's full-mode replay returned 0 at 604,623,449 cycles, exactly the sum of the folded stacks. The 506,361-cycle difference between fast mode and the profile is outside the ranked instruction costs. Profile addresses were resolved against the ELF symbols and identical stacks were combined before rendering. [Debugger profiling guide](https://github.com/nervosnetwork/ckb-standalone-debugger/blob/develop/ckb-debugger/guide.md#performance-analysis-with-flamegraph)

From the repository root, replay the saved baseline and regenerate the raw profile with the local artifacts under `target/`. For future changes, compare fast-mode cycles on the same claims and proof, then confirm with the benchmark command above.

```sh
(cd target/profiling/sphincs-500 && ckb-debugger --tx-file tx.json --script input.0.lock)
(cd target/profiling/sphincs-500/symbolized && ckb-debugger --mode full --tx-file tx.json --script input.0.lock --enable-flamegraph --flamegraph-output ../raw.folded)
```
